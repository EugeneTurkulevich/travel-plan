# demo-trip — вигаданий корінь даних

Мінімальний, але справжній корінь рівня 3 (`STRUCTURE_PROPOSAL.md` §1) — той
самий формат, що й приватний `../travel-data/`, лише з видуманим вмістом.
Призначення: дати новій людині на чому побачити скрипти й скіли тулкіта, не
маючи ще власної бібліотеки місць і без токена до жодної карти.

Усі назви, координати, дати й категорії POI тут **навмисно вигадані** —
країна `ZZ` не існує, містечка `Кам'яний Брід` / `Соколиний перевал` /
`Лісове озеро` вигадані для прикладу. Збіг з реальними назвами випадковий.

## Структура

```
demo-trip/
├── .active-trip              → "demo"
├── places/                    3 картки за schemas/PLACE_SPEC.md
│   ├── zz-kamyanyi-brid.md     повний  — ночівля дня 1
│   ├── zz-sokolyny-pereval.md  базовий — денна зупинка дня 2
│   └── zz-lisove-ozero.md      повний  — ночівля дня 2
└── trips/demo/
    ├── trip.json               профіль БЕЗ map_id — карти немає, це демо
    ├── route.json               2 дні · 3 точки
    ├── overlay/zz-kamyanyi-brid.md   одна картка з «Опис (доповнення)»
    └── exports/                 сюди generate_state.py пише route_state.json
```

## Що показує цей набір

- **Дві глибини одразу** — `zz-kamyanyi-brid`/`zz-lisove-ozero` (ночівлі,
  роль `overnight`) на рівні «повний», `zz-sokolyny-pereval` (денна зупинка,
  роль `visit`) на рівні «базовий»: без секцій «Де зупинитись»/«В'їзд на
  авто»/«Паркування» — і це нормально, вони не обов'язкові до повного рівня
  (`schemas/PLACE_SPEC.md` §2).
- **`poi_categories` — дані поїздки, не код.** `trip.json` цього профілю
  оголошує дві довільні категорії — `local` (🎁 «Гірський виріб») і
  `viewpoint` (🔭 «Огляд») — з іконками й назвами секцій, яких немає в жодній
  реальній поїздці. Прибери демо-профіль — і ці категорії зникають разом з
  ним, код `generate_state.py` про них нічого «не знає» напряму.
  ⚠️ Один нюанс поточної реалізації видно й тут: підпис категорії, який іде в
  `nested_points` (`type_name`), генератор бере зі свого фіксованого
  словника, а не з тексту `section` у `trip.json` — тому в
  `route_state.json` `viewpoint` матиме `type_name: "Оглядові точки"`,
  хоча MD-секція картки називається «Огляд». Це задокументований розрив між
  «яку секцію картки шукати» (дані) і «який підпис показати» (код) —
  `schemas/PLACE_SPEC.md` §3.
- **Overlay зшивається лише одним полем.** `overlay/zz-kamyanyi-brid.md`
  містить тільки `## Опис (доповнення)` — рівно те, що `generate_state.py`
  дійсно додає до попапу (решта секцій overlay, якби вони тут були,
  генератор не читає — `schemas/PLACE_SPEC.md` §5).
- **Профіль без карти.** `trip.json` не має `map_id` — публікація
  (`/publish`, `cloud_push.py`) для цього профілю не має сенсу і не
  перевірялась; демо для самих скриптів побудови стану, не для пайплайна
  публікації.

## Як користуватись

Із кореня репозиторію, без жодного налаштування `.travel-local.json` чи
токена:

```bash
python3 scripts/generate_state.py --data examples/demo-trip
python3 scripts/generate_docs.py  --data examples/demo-trip
python3 scripts/check_limits.py   --data examples/demo-trip
```

Перший запис перезапише `trips/demo/exports/route_state.json` і надрукує
розібрані точки; другий — `trips/demo/ROUTE.md` і `places/CATALOG.md`;
третій прогонить payload проти лімітів воркера (тут усе далеко в межах —
демо-набір навмисно маленький).

Подивитись профіль без запуску генераторів:

```bash
python3 scripts/trip.py --data examples/demo-trip
```

(`trip.py` порахує «карток бібліотеки» на одну більше, ніж карток місця —
рахує всі `*.md` у `places/`, включно зі згенерованим `CATALOG.md`; так само
поводиться і на реальних даних.)

`--data` і `--trip` — різні речі (`trip_ctx.py`): `--data` вибирає **корінь**
даних, `--trip` — **профіль усередині** обраного кореня. Якщо твій
`.travel-local.json` уже вказує на власні дані, самого `--trip demo` замало —
профілю `demo` там немає. Щоб погратись демо-набором незалежно від свого
`data_root`, треба саме `--data examples/demo-trip` (або `TRAVEL_DATA=examples/demo-trip`
в оточенні) — `.active-trip` цього кореня сам підставить профіль `demo`.
