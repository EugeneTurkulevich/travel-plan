# travel-plan

*[English](README.en.md)*

Тулкіт для планування авто-подорожей разом з агентом поверх спільної карти
[trip-map](https://trip-map.web.app) та її MCP-воркера. Карта сама рахує
плечі (OSRM), тримає розклад, версіонує маршрут, зберігає мітки, рейтинги й
обговорення учасників — цей репозиторій відповідає на інше питання: **звідки
береться те, що на неї заливається.**

## Ідея

Найдорожче в плануванні — не маршрут, а **знання про місця**: перевірені
координати, POI з описами й фото, де паркуватись, де зупинитись. Маршрут
перебудовується дешево — переставив дні, зсунув виїзд; знання про місце
дешево не відновлюється, воно назбирується. Тому тут вони живуть **окремо**
від поїздок: одна картка місця в бібліотеці, скільки завгодно маршрутів, які
на неї посилаються. Одну поїздку місце проходить прохідною зупинкою, наступну
— стає повноцінною ночівлею, і картка та сама, без переписування з нуля.

## Два дерева

| | Де | Що |
|:--|:--|:--|
| **тулкіт** | цей репозиторій, публічний | правила, скрипти, схеми, скіли — метод |
| **дані** | окремий каталог, приватний (типово `../travel-data`) | бібліотека місць, профілі поїздок, привʼязки до карт, кеші, токен |

Дані сюди не потрапляють ніколи — ні назва місця, ні `map_id`, ні дата
поїздки (`scripts/check_no_data.py` це перевіряє механічно, гейт нижче).
Завдяки такому поділу репозиторій можна клонувати й одразу під'єднати
**свою** карту — жодного файлу з чужою поїздкою в ньому немає.

## Швидкий старт

```bash
git clone <this-repo>
cp .travel-local.json.example .travel-local.json   # де лежатимуть ТВОЇ дані
```

Відредагуй `data_root` у `.travel-local.json` (дефолт — сусідній каталог
`../travel-data`; резолв шляху: `--data` → `$TRAVEL_DATA` → цей файл →
`../travel-data`, `scripts/trip_ctx.py`). Токен воркера кладеться в `.env`
**кореня даних**, не сюди (зразок змінних — `.env.example`); видається на
карті: ☰ → «🤖 Підключити ШІ-агента…».

Далі — `trip.py new`, щоб почати поїздку з нуля (питання методички: дати,
старт/фініш, кільцевий чи лінійний, інтереси), або `trip.py import <map_id>`,
щоб підхопити карту, яку вже наповнила компанія, і зібрати з неї локальний
профіль і бібліотеку.

Ще нема ні своєї карти, ні даних, а подивитись хочеться просто зараз —
`examples/demo-trip/` це маленький вигаданий корінь даних (без токена, без
`map_id`), на якому працюють генератори й скрипти:

```bash
python3 scripts/generate_state.py --data examples/demo-trip
python3 scripts/generate_docs.py  --data examples/demo-trip
python3 scripts/check_limits.py   --data examples/demo-trip
```

Деталі — `examples/demo-trip/README.md`.

## Що вміють скіли

Скіли (`.claude/skills/`) — головний вміст тулкіта. Кожен пояснює **чому**
саме так, а не тільки що робити: методичка воркера (`trip-map://guide`)
задає правила, скіл — коли й навіщо їх застосовувати в конкретній ситуації.

| Скіл | Навіщо |
|:--|:--|
| `/trip` | показати/перемкнути/створити профіль поїздки — і пояснити, чому сплутати профілі означає залити чужий маршрут поверх свого |
| `/place` | довести картку до потрібної глибини під роль (ескіз → базовий → повний), не переписуючи з нуля — і чому повна картка десяти кандидатів, з яких візьмуть двох, це марнотратство |
| `/plan-day` | перерахувати розклад дня за виміряними (не оціненими на око) плечима — і чому пряма лінія на карті системно оптимістичніша за реальну дорогу |
| `/publish` | залити маршрут у спільну карту через цикл гейтів — і чому один `set_route` цілим маршрутом непомітно вбиває чужі рейтинги й треди на точках, що випали з файлу |
| `/audit` | зібрати список кандидатів на перевірку (координати, фото, розкид сабкарти, ліміти воркера, повнота під роль) — чесно як список, а не вирок «правильно/неправильно» |
| `/alt` | завести кандидата одразу в карті, а не тримати в чаті — і безпечно перенести точку між шарами маршрут/альтернативи, не втративши рейтинги й тред |
| `/handoff` | оформити задачу воркеру, коли локальне рішення випробуване й корисне не лише нам — і чому межа передачі саме там (два типи файлів, ніколи код) |

## Чого тулкіт не робить

- **Не дублює методичку воркера.** `trip-map://guide` — першоджерело
  робочого циклу карти; скіли на неї спираються й посилаються, а не
  переказують своїми словами (вона й так змінюється швидше, ніж встигав би
  оновлюватись дубль).
- **Не тримає `trip_rules` у собі.** Правила конкретної поїздки живуть на
  карті, власник міняє їх без нашої участі. У профілі (`trip.json`) є лише
  `poi_categories` — таблиця «яку MD-секцію якою іконкою писати», а не копія
  самих правил.
- **Не чіпає користувацькі дані.** Мітки, рейтинги, треди обговорення,
  ночівлі й парковки учасників (`get_places`) — дзеркалимо (`live_mirror`),
  не авторимо. Створення й видалення альтернатив — на явне прохання, ніколи
  мовчки.

## Гейт публічності

```bash
python3 scripts/check_no_data.py
```

Сканує файли, які реально підуть у git, і падає, якщо в них зʼявився
`map_id`, назва місця з бібліотеки, категорія POI чи дата конкретної поїздки
з даних поруч — а також секрети й абсолютні шляхи користувача. `examples/` з
цього гейту навмисно виключений: усе, що там лежить, вигадане для показу.

## Походження

Репозиторій зʼявився як переїзд із двох попередників, де дані й код були
змішані в одному дереві. Для роботи з тулкітом сьогодні це знати не
обов'язково — історія рішень і хід переносу описані окремо, в
`MIGRATION_PLAN.md` і `STRUCTURE_PROPOSAL.md`, як запис того, як і чому
дійшли до поточної структури, а не як інструкція до дії.
