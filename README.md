# travel-plan

Тулкіт для планування авто-подорожей разом з агентом поверх спільної карти
[trip-map](https://trip-map.web.app) та її MCP-воркера.

Карта вміє багато сама: міряє плечі через OSRM, рахує розклад, версіонує
маршрут, тримає мітки, рейтинги й обговорення учасників. Цей репозиторій — про
те, **як з нею працювати**: бібліотека досліджених місць, що переживає окремі
поїздки, профілі маршрутів, перевірки перед публікацією і скіли, які все це
зв'язують.

> 🚧 **У розробці.** Іде міграція з двох репозиторіїв-попередників
> ([`travel2026`](https://github.com/EugeneTurkulevich/travel2026),
> [`travel202609`](https://github.com/EugeneTurkulevich/travel202609)).
> Порядок робіт — [MIGRATION_PLAN.md](MIGRATION_PLAN.md), проєктні рішення —
> [STRUCTURE_PROPOSAL.md](STRUCTURE_PROPOSAL.md). До завершення Ф5 робочим
> каналом до карти лишається старий репозиторій.

## Ідея

Найдорожче в плануванні — не маршрут, а **знання про місця**: перевірені
координати, POI з описами й фото, паркування, практичне. Маршрут
перебудовується дешево, знання — ні. Тому тут вони живуть окремо від поїздок:
одна картка місця, скільки завгодно маршрутів, які на неї посилаються.

## Два дерева

| | Де | Що |
|:--|:--|:--|
| **тулкіт** | цей репозиторій, публічний | правила, скрипти, схеми, скіли |
| **дані** | окремий приватний каталог | місця, маршрути, привʼязки до карт, кеші, токен |

Дані сюди не потрапляють ніколи — ні місця, ні `map_id`. Завдяки цьому
репозиторій можна клонувати й користуватись ним зі своєю картою.

## Початок роботи

```bash
git clone …
cp .travel-local.json.example .travel-local.json   # де лежатимуть твої дані
python3 scripts/trip.py list
```

Токен воркера кладеться в `.env` **кореня даних** (зразок — `.env.example`);
видається на карті: ☰ → «🤖 Підключити ШІ-агента…».

Далі — `trip.py new` для нової поїздки або `trip.py import <map_id>`, щоб
підхопити вже наповнену карту (обидві — Ф7).
