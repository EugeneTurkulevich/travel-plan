# scripts/ — інструменти тулкіта

Запуск завжди з кореня репозиторію. Тільки stdlib — жодних залежностей, тому
`requirements.txt` тут немає й не має зʼявитись без вагомої причини.

Дані ці скрипти **не містять**: усе, що специфічне для конкретної поїздки,
приходить із кореня даних через `trip_ctx`. Перевіряє це `check_no_data.py` (Ф7).

## Статус: що лишається в нас, а що йде у воркер

Рівень 1 з [STRUCTURE_PROPOSAL.md](../STRUCTURE_PROPOSAL.md) §1 — «випробуване
локально й корисне всім передаємо на реалізацію в MCP». Щоб це не лишалось
декларацією, кожен скрипт має статус.

| Скрипт | Статус | Підстава |
|:--|:--|:--|
| `trip_ctx.py` · `trip.py` | 🏠 локальний назавжди | вибір профілю і резолв шляхів — клієнтське поняття, воркер про нього не знає |
| `generate_state_from_md.py` → `generate_state.py` | 🏠 локальний назавжди | MD → JSON; воркер про Markdown нічого не знає |
| `cloud_push.py` | 🏠 локальний · **на переробку (Ф5)** | стане виконавцем плану публікації замість «залий усе одним `set_route`» |
| `mcp_probe.py` | 🏠 локальний | виклик тулів, поки MCP не підключений у сесії |
| `build_schedule.py` | ⏳ частково передано | `map-server/TODO.md:12` — таймінг-модель портується на воркер (`compute_schedule`), `set_route` уже рахує розклад. Лишається **рішення** (старт, `stay`, `friction`) |
| `osrm_legs.py` | ⏳ частково передано | `measure_legs` рахує послідовні плечі; у нас матриця N×N для проєктування |
| `find_poi_photos.py` | ⏳ частково передано | `find_photos` — один запит; у нас масовий прохід з 3 стратегіями |
| `merge_cloud_photos.py` | ⏳ поглинається `pull_map.py` (Ф1/Ф5) | вужча версія загального pull-before-push |
| `check_marks.py` → `check_threads.py` | 🚀 кандидат · **неповний (Ф5)** | читає лише мітки, а треди тепер є й на місцях (`live.threads`). Виміряно 04.08: 20 тредів, усі на альтернативах |
| `audit_coords_osm.py` | 🚀 кандидат | пакетний аудит координат по Overpass корисний кожному користувачу карти |
| `audit_coords.py` | 🩹 **зламаний** | `ROOT` — абсолютний шлях `~/Documents/GitHub/…`, якого не існує. Полагодити через `trip_ctx` (Ф2) або злити з `audit_coords_osm.py` |
| `check_submap_spread.py` | 🚀 кандидат | правило «POI ≤10–15 км від точки» вже в методичці, а валідатора немає |
| `check_trip_rules.py` | 🏠 локальний | звіт по навантаженню днів — наше уявлення про темп |

🏠 у нас назавжди · ⏳ частково або повністю передано воркеру · 🚀 кандидат на
передачу · 🩹 зламаний

Передача — через `/handoff`: файл у `../map-server/docs/` + рядок у його
`TODO.md`, ніколи код. Статус оновлюється тут-таки.
