# scripts/ — інструменти тулкіта

Запуск завжди з кореня репозиторію. Тільки stdlib — жодних залежностей, тому
`requirements.txt` тут немає й не має зʼявитись без вагомої причини.

Дані ці скрипти **не містять**: усе, що специфічне для конкретної поїздки,
приходить із кореня даних через `trip_ctx`. Перевіряє це `check_no_data.py` (Ф7).

## Статус: що лишається в нас, а що йде у воркер

Рівень 1 з [STRUCTURE_PROPOSAL.md](../STRUCTURE_PROPOSAL.md) §1 — «випробуване
локально й корисне всім передаємо на реалізацію в MCP». Щоб це не лишалось
декларацією, кожен скрипт має статус.

| Скрипт | Статус | Підстава |
|:--|:--|:--|
| `trip_ctx.py` · `trip.py` | 🏠 локальний назавжди | вибір профілю і резолв шляхів — клієнтське поняття, воркер про нього не знає |
| `generate_state.py` | 🏠 локальний назавжди | MD → JSON; воркер про Markdown нічого не знає. Портовано з попередника (MD+INDEX.md), який видалено — заміщений і нікуди не імпортується (Ф4/Ф7) |
| `cloud_push.py` | 🏠 локальний · **на переробку (Ф5)** | стане виконавцем плану публікації замість «залий усе одним `set_route`» |
| `pull_map.py` | 🏠 локальний | знімок карти в `live_mirror.json` (6 read-тулів + `get_route_brief` на кожну збірку з `list_alts`, шар `route_alts`). Доказ коректності міграції, а згодом — обовʼязковий pull перед пушем і основа `trip.py import` |
| `mcp_probe.py` | 🏠 локальний | виклик тулів, поки MCP не підключений у сесії |
| `build_schedule.py` | ⏳ частково передано | `map-server/TODO.md:12` — таймінг-модель портується на воркер (`compute_schedule`), `set_route` уже рахує розклад. Рішення (старт, `stay`, `friction`) — у `route.json` даних (Ф7), скрипт лише рахує |
| `osrm_legs.py` | ⏳ частково передано | `measure_legs` рахує послідовні плечі; у нас матриця N×N для проєктування. Координати — з бібліотеки місць (Ф7), не з коду |
| `find_poi_photos.py` | ⏳ частково передано | `find_photos` — один запит; у нас масовий прохід з 3 стратегіями |
| `merge_cloud_photos.py` | ⏳ **поглинуто** `pull_map.py` | тягнув лише фото POI з `get_route`; загальний pull робить те саме ширше. Видалити після Ф5, коли `plan_push.py` перебере звірку на себе |
| `check_threads.py` | 🏠 локальний · частково реалізовано воркером 08.08 | мітки **і треди місць**: треди живуть плоско за id і є в обох шарів. Виміряно 04.08 — 20 тредів, з них 19 на альтернативах, тобто попередник (`check_marks.py`) не бачив жодного. Мітка `threads_reviewed_until` у профілі тримає гейт від постійного червоного. `list_marks`/`get_route` отримали опційний `since` (epoch ms) — `map-server/docs/MARKS-THREADS-SINCE-DESIGN.md`, задеплоєно. Не консумуємо в `pull_map.py`: той тягне ПОВНЕ дзеркало для інших споживачів (diff маршруту в `plan_push.py` тощо), звужувати його під потреби одного скрипта — свідомо відкладене рішення, не забуте |
| `check_marks.py` | 🗑️ **заміщений** `check_threads.py` | лишений тимчасово; видалити, коли новий відпрацює кілька циклів публікації |
| `audit_coords_osm.py` | 🏠 локальний · метод перенесено воркером 08.08 | пакетний аудит координат по Overpass. `geocode` отримав опційний `crosscheck` (`map-server/docs/GEOCODE-CROSSCHECK-DESIGN.md`, задеплоєно) — той самий алгоритм (транслітерація, токен-збіг, найближчий серед тезок), портований з цього скрипта, але точково на один виклик `geocode`. Скрипт лишається — крос-перевірка не ретроактивна, картки, геокодовані до 08.08 чи без `crosscheck`, перевірить лише пакетний прогін по всій бібліотеці |
| `audit_coords.py` | 🏠 локальний | полагоджено у Ф2 (був мертвий абсолютний шлях), у Ф7 позбувся словника «файл → місто» — місто й країна беруться із самої картки |
| `check_submap_spread.py` | 🏠 локальний назавжди | правило «POI ≤10–15 км від точки» перевіряє `route_state.json` — наш НАМІР до пушу, якого на карті ще нема. Воркер (`map-server/docs/POI-SPREAD-VALIDATION-DESIGN.md`, задеплоєно 08.08) тепер рахує те саме для **живих** даних (`get_route`/`list_alt_route` → топлевел `poi_spread`, `add_poi`/`update_poi` → `poi_spread_km`/`poi_spread_warning`) — доповнює цей скрипт, не заміняє: те, чого ще нема на карті, воркеру нізвідки перевірити. Винятки (острови) — у `submap_allow.json` даних, не в коді |
| `check_limits.py` | 🏠 локальний | ліміти воркера локально, у **байтах**: кирилиця в UTF-8 займає два байти, `len()` рядка занижує payload удвічі. Байтовий guard на 900_000 (не 900*1024 — виправлено 07.08, було лагідніше за реальний ліміт сервера). Повʼязана вада `update_poi` (`map-server/docs/POI-STRICT-UPDATE-LOCK-DESIGN.md`) — виправлена воркером 08.08 (`validatePoi` тепер перевіряє лише поля з `fields`), нашого коду це не торкалось напряму |
| `check_trip_rules.py` | 🏠 локальний | звіт по навантаженню днів — наше уявлення про темп |
| `check_no_data.py` | 🏠 локальний назавжди | гейт публічності: сканує репозиторій на дані поїздки. Потрібен саме нам — за один день я двічі пропустив очима те, що знайшлось лише скануванням |
| `plan_push.py` | 🏠 локальний | diff наміру проти дзеркала → план із правильних тулів. **Не має режиму виконання** і не матиме |
| `sync_from_map.py` | 🏠 локальний | напрямок карта → дані; наявні картки не чіпає, розбіжності показує |

🏠 у нас назавжди · ⏳ частково або повністю передано воркеру · 🚀 кандидат на
передачу · 🗑️ заміщений або разовий

Передача — через `/handoff`: файл у `../map-server/docs/` + рядок у його
`TODO.md`, ніколи код. Статус оновлюється тут-таки.
